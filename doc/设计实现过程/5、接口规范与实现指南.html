记忆/知识管理系统 · 接口规范与实现指南

一份文档两种用途：另一个会话拿着它能直接开发；新人读着它能理解系统。

包含：核心对象 · 四接口定义 · 存储契约 · 实现要点 · 完整流程示例

①系统总览（30 秒理解）

先建立心智模型，再看接口就顺了。

一句话

系统 = 一个锚点 ＋ 四类知识 ＋ 一张网，由四类操作（记忆/蒸馏/收录/关联）驱动，形成"沉淀 → 关联 → 复用 → 再沉淀"的闭环。

API 分层

┌─────────────────────────────────────────────┐
│ 业务接口层（面向四操作 + 蒸馏/导入）          │
│   MemoryWriter 写 · MemoryReader 读          │
│   Distiller 蒸馏 · Importer 存量导入         │
├─────────────────────────────────────────────┤
│ 引擎接口层（可插拔）                         │
│   NetworkStore：SQLite（默认）/ Neo4j / Memory │
└─────────────────────────────────────────────┘

第一原则（贯穿所有设计）

  • 检索 = 系统（机械、可验证）——search/traverse 是系统行为
  • 判断 = 模型（读 summary 判断）——search 返回轻量字段，不读全文
  • 锚 = 原文（Layer 0 保真）——任何知识可溯源

②核心概念（新人必读）

概念含义
锚点对话原始记录（保真、不可变）。存 anchors/ 目录 md 文件。一切知识的溯源根
知识事情（发生了什么）/ 经验（怎么办）/ 常识+共识（是什么）。存 knowledge/ 目录 md + frontmatter
网知识之间的关联（挂靠/关联/溯源），SQLite 边表
四操作记忆（对话→锚点）· 蒸馏（对话→知识）· 收录（告知→知识）· 关联（建边）
三级粒度title 扫（候选列表）→ summary 判（是不是这件事）→ file 钻（细节原文）
蒸馏流程（重点）：你说"帮我蒸馏" → AI 整体整理当前对话 → 产出候选清单（含关联建议）→ 你 review 勾选 → 确认的入库 + 按确认的关联建边。前期全人工确认，规则沉淀是后续方向。

③核心对象（类型定义，开发直接抄）

所有接口的参数建立在以下类型上。

# —— 枚举 ——
class KnowledgeType(Enum): EVENT; METHOD; FACT
class Scope(Enum): UNIVERSAL; DOMAIN; PERSONAL
class Status(Enum): DRAFT; EVOLVING; SETTLED; DEPRECATED
class EdgeType(Enum): PARENT; LINK; TRACE
class RefType(Enum): IDEV; MR; UAT; URL
class SourceType(Enum): USER_DECLARED; CONVERSATION_DISTILLED
class Decision(Enum): KEEP; EDIT; REJECT

# —— 值对象 ——
class Source:
    type: SourceType      # 知识来源
    ref: str              # 锚点引用（anchor_id 或路径）

class ExternalRef:
    type: RefType         # idev | mr | uat | url
    value: str

class Knowledge:          # 知识本体（create/update 的主体）
    type: KnowledgeType
    scope: Scope
    title: str
    summary: str          # 判断用摘要（3~5 句）
    body: str             # 正文
    sources: list[Source]
    parents: list[str]    # 多父挂靠（id 列表，DAG）
    links: list[str]      # 关联（id 列表）
    external_refs: list[ExternalRef]
    status: Status = Status.DRAFT

class SearchHit:          # search 返回的候选条目
    id: str
    title: str
    summary: str          # 供模型判断，不读全文
    file: str             # 供下钻
    type: KnowledgeType
    scope: Scope
    score: float          # RRF 融合分（排序）

class DistillCandidate:   # 蒸馏产出的单条候选
    type: KnowledgeType
    scope: Scope
    title: str
    summary: str
    body: str
    suggested_parents: list[str]   # 关联建议（AI 给，review 可改）
    suggested_links: list[str]
    sources: list[Source]          # 自动带 conversation_distilled + ref
    decision: Decision = Decision.KEEP

④接口定义（四接口，开发直接抄）

MemoryWriter · 写接口（新增/更新）

# 职责：保证 md 真值 + 五张表一致性（写入的唯一入口）
class MemoryWriter:
    def save_anchor(self, content: str, title: str = None) -> str
        # 记忆：对话 → 锚点文件；返回 anchor_id（供 sources.ref）

    def create_knowledge(self, k: Knowledge) -> str
        # 蒸馏/收录：写一条知识（生成 md + 同步五张表）；id 由接口自动生成并返回

    def update_knowledge(self, id: str, **changes) -> None
        # 改版：只改指定字段（None=不变）；改 body 自动 FTS delete+insert

    def deprecate_knowledge(self, id: str) -> None
        # 废弃：status → DEPRECATED，留痕不删

    def add_edge(self, from_id: str, to_id: str, edge_type: EdgeType) -> None
    def remove_edge(self, from_id: str, to_id: str, edge_type: EdgeType) -> None

    def add_external_ref(self, node_id: str, ref_type: RefType, ref_value: str) -> None
    def remove_external_ref(self, node_id: str, ref_type: RefType, ref_value: str) -> None

MemoryReader · 读接口（检索）

# 职责：系统机械检索，返回轻量字段供模型判断
class MemoryReader:
    def search(self, query: str, limit: int = 10,
               type: KnowledgeType = None, scope: Scope = None) -> list[SearchHit]
        # 双路召回（FTS 字面 + 向量语义 + RRF 合并）→ 候选（id/title/summary/file）

    def traverse(self, start_id: str, depth: int = 2,
                 edge_types: list[EdgeType] = None) -> list[tuple[str, EdgeType, int]]
        # 图遍历：返回 (节点id, 边类型, 跳数)

    def get(self, id: str) -> Knowledge | None
        # 按 id 取完整知识（含 external_refs / sources / links）

Distiller · 蒸馏接口

# 职责：从对话产出候选（不落库）→ 用户 review → 确认入库
class Distiller:
    def distill(self, anchor_id: str = None, topic: str = None) -> list[DistillCandidate]
        # anchor_id 为空 → 蒸馏当前上下文对话（实时，AI 直接整理）
        # anchor_id 指定 → 蒸馏该锚点完整对话（早期/存量，读文件）
        # 产出候选清单（含关联建议），不落库

    def confirm_distill(self, candidates: list[DistillCandidate]) -> list[str]
        # KEEP/EDIT → create_knowledge + 按确认的关联建边；REJECT → 跳过
        # 返回入库 id 列表

Importer · 存量导入

# 职责：历史对话批量导入（与增量共用管道，只是批量）
class Importer:
    def import_history(self, source_dir: str,
                       time_range: tuple[str, str] = None,
                       mode: str = 'backfill') -> ImportResult
        # 扫描历史 JSONL → 批量生成锚点 → 批量蒸馏 → 建索引
        # mode: backfill（全量）/ incremental（增量）

class ImportResult:
    anchors_created: int
    knowledge_created: int
    errors: list[str]

接口约定的关键点

约定说明
id 生成create_knowledge 接口自动生成（k-0003 序列），调用方不用管
蒸馏确认前期全人工 review；规则沉淀是后续方向（暂不实现）
存量导入确认前期逐个 review；确认稳定后改为自动执行（过程纠正会记录下来）
无顶层门面四接口分开直接用；遇到必须合并的问题再合并
get 返回返回完整 Knowledge（含 external_refs 等），更多返回便于开发优化

五张表（schema.sql，见同目录文件）

表作用关键
nodes知识本体索引（无 body）rowid 是四表关联键；id 业务键
nodes_ftsFTS5 字面检索title+body 两列，trigram 分词
nodes_vec向量语义检索sqlite-vec，embedding float[N]
edges网的关系parent / link / trace
external_refs知识↔真实世界idev / mr / uat / url

⑥实现要点（关键逻辑，直接指导开发）

create_knowledge 内部逻辑（一致性核心）

# 1. 生成 md 真值文件
path = f"knowledge/{k.id}_{k.title}.md"
write_md(path, frontmatter(k), k.body)

# 2. 同步五张表（一个事务，原子）
with db.transaction():
    rowid = INSERT nodes(id, file, title, summary, type, scope, status, created, updated)
    INSERT nodes_fts(rowid, title, body)        # 正文从 md 读入
    INSERT nodes_vec(rowid, embedding)          # summary 算向量
    for p in k.parents:  INSERT edges(k.id, p, 'parent')
    for l in k.links:    INSERT edges(k.id, l, 'link')
    for r in k.external_refs: INSERT external_refs(...)

FTS 更新（FTS5 不支持 UPDATE）

# update_knowledge 改 body 时：
INSERT INTO nodes_fts(nodes_fts, rowid, title, body) VALUES('delete', :rowid, :old_title, :old_body)
INSERT INTO nodes_fts(rowid, title, body) VALUES(:rowid, :new_title, :new_body)

检索链路（search 内部）

# 1. 双路召回
fts_rowids  = SELECT rowid FROM nodes_fts WHERE nodes_fts MATCH :query
vec_rowids  = SELECT rowid FROM nodes_vec WHERE embedding MATCH :query_vec ORDER BY distance LIMIT N

# 2. RRF 合并（两路分数不可比，用排名融合）
score = Σ 1/(60 + rank)   # 双路命中者优先

# 3. JOIN nodes 取轻量字段
SELECT id, title, summary, type, scope, file FROM nodes WHERE rowid IN (...)

rowid 对齐（易错点）

# nodes 和 nodes_fts/nodes_vec 必须用同一个 rowid（一个事务内）
rowid = conn.execute("INSERT INTO nodes(...)").lastrowid
conn.execute("INSERT INTO nodes_fts(rowid, ...)", (rowid, ...))

rebuild（兜底，幂等）

# 扫描 knowledge/*.md → 重建 nodes → 重建 FTS → 重建 vec → 重建 edges
def rebuild():
    clear_all_tables()
    for md in scan("knowledge/*.md"):
        k = parse_md(md)
        create_knowledge(k)

⑦完整流程示例（开发 + 理解用）

流程一：收录业务流程

# 用户告知需求单流程（收录 → create_knowledge）
writer.create_knowledge(流程 k-0003, type=FACT, scope=DOMAIN,
                        sources=[user_declared])
writer.create_knowledge(环节 k-0010, type=FACT, scope=DOMAIN,
                        parents=[k-0003])        # 挂靠总流程
writer.add_edge(k-0010, k-0030, EdgeType.LINK)  # 关联代码

流程二：蒸馏一段开发对话

# 用户说"帮我蒸馏"
cands = distiller.distill()                     # 当前上下文 → 候选（含关联建议）
# 用户 review：k1 keep / k2 edit / k3 reject
ids = distiller.confirm_distill(cands)          # 确认的入库 + 建关联

流程三：下次复用（改需求单）

hits = reader.search("改一下审批环节")           # 候选（summary 判断）
rel  = reader.traverse("k-0010", 2)             # 父流程/代码/经验
full = reader.get("k-0010")                     # 下钻完整知识

流程四：存量导入历史会话

result = importer.import_history("~/.claude/projects/", mode="backfill")
# 前期：每个候选逐个 review；确认稳定后自动执行（纠正过程会记录下来）

⑧边界与约定（实现前必读）

项约定
蒸馏确认前期全人工 review（候选 → 勾选 → 入库）；规则沉淀是后续方向，暂不实现
存量导入确认前期逐个 review；确认稳定后改自动执行，纠正过程会记录用于规则沉淀
embedding 服务向量要外部模型算（API 或本地）——这是引入向量表唯一的外部依赖；N 维由所选模型定
无 body 存储正文只在 md 文件一处；FTS 索引 rebuild 时从 md 读入——不存双份
中文分词FTS5 必须用 trigram tokenizer（默认对中文整段切，子串搜不到）
错误处理create/update 在事务内原子；失败回滚，md 文件与索引保持一致
幂等性rebuild / import_history 可重复执行（IF NOT EXISTS + 全量重建）
