# 蒸馏提炼规范 · 事件模式（DISTILL_EVENT）

> 场景：蒸馏「一次会话 / 一段时间里做了**一件事**」——有起因-过程-结果，主体是**事件**。
> 产出的形状：**一棵树**——1 个主事件（根）+ N 个环节（挂靠根）。
> 先读 `DISTILL_GUIDE.md`（共用篇），再读本文档。

## 0. 一句话定位

- 判断「是不是事件模式」：这段对话围绕的是**一件事的发生与解决**，还是**一个领域的结构描述**？
  - 「一件事」（有起因→过程→结果）→ **事件模式（本文档）**
  - 「一个领域长什么样」（结构/状态机/流程规则）→ **领域模式（DISTILL_DOMAIN.md）**

## 1. 核心原则：先识事件，再拆环节（最高优先级）

- 蒸馏任何一段对话，**第一步不是逐条抽事实，而是先回答**：这段对话围绕的「主体事件」是什么？
- 主体事件 = 一件事（一句话能说清「什么起因、做了什么、什么结果」）。
- **先立主事件，再往下拆环节**。没有主事件就拆环节 → 产出一堆游离事实，是最大反模式。

## 2. 蒸馏结构：主事件 + 环节挂靠（一棵树）

- 结构：**1 个主事件**（type=`event`，根节点，无 parent）→ **N 个环节**（挂靠根，`suggested_parents` 指向根）。
- 环节 type 看内容：
  - 具体某件事 → `event`
  - 一条规则/结论 → `fact`
  - 一套做法/流程 → `method`
- **简单对话允许 N=0**（只 1 个主事件，不硬拆——硬拆就是造噪声）。

## 3. 粒度：两层，先聚后拆

- 默认**两层**：主事件 + 环节。环节不再往下拆（除非环节本身大到可独立成事件，此时它自己升级成主事件）。
- **拆环节的唯一开关 = 可独立复用**：这个环节脱离本次对话，还能否被单独检索到并复用？
  - 能（有独立结论 / 可复用的做法）→ 拆成环节
  - 不能（只是主事件的一个步骤，无独立结论）→ **不拆，写进主事件 body**
- **两个 body 纪律**（防重复）：
  - 主事件 body 只写**事件级**：起因 → 关键环节一句话索引 → 结果。
  - 环节 body 写**环节级**：这个环节本身怎么做 / 结论是什么。
  - 禁止主事件 body 复述环节细节。

## 4. 判定标准：什么值得沉淀（层级闸门）

- **闸门一（要不要蒸）**：有无可复用结论/做法/决策？纯操作、闲聊、无结论 → 不蒸。
- **闸门二（蒸成主还是环）**：能独立成「一件事」→ 主事件；只是主事件的一环 → 环节。
- **闸门三（环拆不拆）**：可独立复用 → 拆；否则并入主 body。
- **三把尺子筛环节**：①有独立结论 ②能独立检索 ③复用时不缺上下文。

## 5. event 过程模板（body 写法）

**主事件 body**：

```
起因/背景：为什么做这件事（一句话）
过程：关键环节一句话索引（环节名 → 结论）
结果/结论：最终达成什么
```

**环节 body**（按 type 选型）：

- 环节是 `event`：起因 → 做法 → 结果（一句话级）
- 环节是 `fact`：规则/约束原文 + 依据（为什么这么定）+ 触发条件 / 违反后果
- 环节是 `method`：步骤 1..n + 依据（为什么这么做）+ 复用边界

## 6. 场景策略

- **存量锚点**：`Read s-*.md` → 先识主事件 → 拆环节 → 出候选。
- **进行中对话**：直接用当前上下文 → 同上。
- **跨多段对话的同一件事**：先 `search` 找已蒸的主事件 → 有则 `edit`/挂靠到已有主事件，**不新建平行主事件**。

## 7. few-shot（示例）
